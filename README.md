# Logistics Insight Engine

An interactive dashboard that turns raw delivery-operations CSV exports (orders, warehouses, fleet, weather, feedback) into an explainable story about *why* deliveries fail or run late — broken down by city, warehouse, driver/fleet, and customer sentiment.

## What it does

- Loads sample logistics data (orders, clients, warehouses, warehouse logs, feedback, weather, fleet logs, drivers) from static CSVs.
- Joins them by `order_id`, `warehouse_id`, and `driver_id`.
- Classifies every failed or late order under a single, consolidated root cause (order status, fleet/driver issue, or weather/traffic/event context).
- Lets you filter the entire view by city, client, or warehouse.
- Surfaces the findings as charts, tables, a plain-language narrative summary, and a short list of recommendations.

## Getting started

```bash
# install dependencies
npm install

# start the dev server
npm run start

# type-check and build for production
npm run build
```

The app expects its data files at `public/assets/data/*.csv` — see [PROJECT_STRUCTURE.md](./PROJECT_STRUCTURE.md) for the expected filenames and columns.

## Using the dashboard

1. **Filter toolbar** — choose a city, client, and/or warehouse, then click **Get** to apply the filter (there's a short debounce so rapid changes don't trigger repeated recalculation).
2. **Metric cards** — total orders, incidents flagged, failure rate, and active warehouses for the current filter selection.
3. **Insight panel** — a narrative summary of the highest-risk city, dominant failure trigger, and busiest warehouse for the current slice, plus a handful of recommended actions. If too few orders match the current filters, this panel says so rather than overstating a pattern from a small sample.
4. **Analytics sections** — each has a Graphical/Tabular toggle:
   - **Delay reason breakdown** — top consolidated failure reasons.
   - **City disruption hotspots** — cities with the highest failure rate.
   - **Warehouse friction** — warehouses most tied to visible incidents.
   - **Customer sentiment** — feedback sentiment distribution for the current selection.

## Known limitations

- All data processing runs client-side against static CSVs — there's no live backend, so this is intended for sample/demo data rather than production-scale datasets.
- The failure-reason classification priority (order status → fleet notes → weather/traffic/event → unknown) is a best-effort reconstruction of the intended business logic; exact category counts may not match a report generated by a different script, since the underlying weather/traffic/event/fleet fields in the sample data are independently randomized per row.
- `FleetLog` and `Driver` types currently live locally in `useLogisticsAnalytics.ts` rather than in the shared `src/types/logistics.ts` — worth consolidating.
